# 单视频学习工作台

2026-10-26：在既有总结和追问能力上增加原文核对、本地笔记及 Markdown 导出。沿用现有品牌、匿名会话和服务器保留期限，不新增账号、数据库服务或付费依赖。

## 使用方式

1. 输入 YouTube / Bilibili / 抖音链接。处理时显示阶段、已用时间和生成骨架；不直接显示模型生成中的 JSON。
2. 在“总结／原文／追问”间切换。总结、画面和问答时间引用打开相应原文位置，没有对应字幕时明确提示；原文支持关键词搜索及前后命中导航。
3. YouTube / Bilibili 原视频链接携带秒数，Bilibili 保留分 P；抖音只打开原视频，需按显示时间手动定位。SenseVoice 时间为估算，原生字幕和 Whisper 的识别时间也不保证精确。
4. 章节“解释这一段”复用现有追问。个人笔记随编辑自动保存，成功问答自动入库，失败或未完成的问答不会作为成功内容持久化。
5. 笔记库可按标题搜索、按最近查看排序、重新打开或确认删除。Markdown 导出包含视频链接、来源、总结、画面描述、个人笔记及成功问答，可选择包含字幕。

手机端切换追问后自动定位到对话区域。对话输入区按动态视口与安全区布局，适配软键盘缩小视口；输入法组合期间 Enter 不触发提交。桌面保留总结/原文与追问双栏。

## 学习辅助

- 展开“学习辅助”，输入术语后选择“解释术语”。提示要求检索视频、引用时间，并将缺失依据与补充知识明确分开；结果进入当前问答。
- “生成复习题”请求最多三道开放题，只要求题目。作答后点击该条回答的“查看参考答案”，再发起独立追问；请求携带原题，避免较早题目超出服务端对话窗口。两步各使用一次现有追问接口，沿用鉴权、限流、费用与期限。题目超过 3200 字符时提示选取其中一题追问。
- 字幕、总结要点和成功回答可“摘录”，按来源、正文和时间去重。在总结下方可查看、定位或移除；导出包含来源标签和已有时间。AI 问答摘录保留原回答内的引用，不伪造额外时间。
- 在线分析不可用时，术语解释、生成复习题和参考答案均禁用；已有摘录仍可阅读、删除、导出。保存失败沿用原有内存保留和重试机制。
- 数据库与笔记格式仍为版本 1，新增可选 `excerpts`（ID、来源类别、正文、可选时间范围、创建时间）及问答 `purpose`（普通问题/术语/复习题/参考答案）；旧笔记缺少字段时按空摘录及普通问答处理，无需迁移或清空存储。

学习提示约束不等于模型质量保证；当前浏览器验收使用确定性回答，真实视频上的题目准确性仍需后续评测。

## 学习进度与复习记录

2026-10-29：在“学习进度与复习”展开章节清单，逐章勾选已学，也可取消。每一章可直接查看对应原文，估算时间仍明确标注。状态从已标记章节计算：没有标记为“待学习”，部分标记为“学习中”，全部标记为“已学完”；无章节不显示完成进度，仍可核对全文和记录复习。此标记由用户主动操作，不代表已观看视频或掌握内容。

- 笔记库同时支持标题搜索和学习状态筛选，每篇显示章节进度及复习次数；筛选不会改变“备份全部笔记”的范围。
- 进度与复习在当前浏览器自动保存，分析过期或服务器重启后仍可更新；不延长追问资格。保存失败时保留当前页面记录，可重试保存和导出。

- 有效缓存复用同一分析的进度；新分析另建笔记，从头记录，旧进度留在原笔记。进度只对应当前笔记的章节，不在不同视频或分析间套用。
- JSON 备份包含学习记录，导入保留；仅学习记录有差异也按冲突副本处理。缺省字段与显式空记录视为相同内容。Markdown 包含总进度、复习次数、最近日期（ISO 格式）和每章学习标记。

## 本地与服务器的边界

- IndexedDB 数据库 `vidsnap-notebook`，版本 1，`notes` store 以独立笔记 `id` 为键。每条记录有格式版本、分析结果、来源、字幕、成功问答、个人笔记和创建/更新/查看时间。
- 保存当前浏览器的文本快照；不保存关键帧图片、帧 URL 或签名。画面描述保留，刷新后的笔记用文字占位，原始媒体仍按现有策略清理。
- 浏览器存储可能被清理，不提供跨设备同步或永久存储保证。建议导出备份。保存失败时保留页面内容、提示重试保存，并允许导出，不自动删除旧笔记。
- 服务器正文/追问仍保留 1 小时，帧仍保留 2 小时；缓存命中不续期。本地保存不会延长在线追问资格。
- 打开本地笔记后检查当前匿名会话的分析状态。删除、过期或服务重启导致分析不可用时，本地正文仍可阅读/导出；重新分析会创建新笔记与问答上下文，旧问答留在旧笔记中。
- 有效的同一分析缓存复用当前笔记，不清空该笔记的个人笔记和问答。删除本地笔记不调用服务器 DELETE；服务器临时数据仍按期限清理。
- 在途分析支持当前标签页刷新后尝试恢复一次；连接中断后可手动恢复。恢复仅加入同会话的原执行或读取有效缓存，找不到时提示重新分析，不自动启动新任务。没有收到合法 `result` 的 EOF 明确报错；失败前已有笔记不清空。服务器重启、多进程及持久任务恢复尚未实现。

- 导入只恢复本地文本，不延长服务器保留时间，不恢复登录态或服务器重启前的追问资格。打开笔记后仍按当前匿名会话检查在线分析；不可用时可阅读、编辑、导出，或主动重新分析。

## 刷新与连接恢复

`sessionStorage` 的 `vidsnap-pending-process` 保存当前标签页的视频链接、首次开始时间和已收到的分析 ID；读取链接时按平台规则规范化，不含访问码、会话凭据或模型正文。线索最长保留 2 小时，不延长服务器的正文/帧期限。成功后清除，无效线索不参与恢复，服务器确认不可恢复后清除。浏览器禁止存储时提示保持页面打开，仍可完成当前分析与导出。

刷新后先读取本地笔记，再自动尝试一次恢复；后续不循环重连。EOF/网络中断保留恢复按钮，401 重新验证后可再恢复，429 按 `Retry-After` 等待；404、终止错误后可手动重新分析。“不再恢复这次分析”只移除本标签页线索，不取消服务器执行。直接再次提交链接属于用户发起的普通分析。

仅在当前 Node 进程、原匿名会话和有效内容期限内可用。抖音短链接完成后需已有分析 ID 才能从缓存找回；若首次元信息进度尚未收到且执行已经结束，恢复会提示不可用。恢复不回放模型 token，只接收最新阶段和最终校验后的结果。

## 兼容接口

`POST /api/process` 保持原 SSE 事件和字段，结果新增：

| 字段 | 含义 |
| --- | --- |
| `platform` / `canonicalUrl` | 平台和由已解析 ID 构造的原视频规范链接 |
| `expiresAt` / `framesExpireAt` | 正文与帧的服务器到期时间（毫秒，帧时间可缺省） |
| `transcription.provider` | `builtin`、`sensevoice`、`whisper` 或旧缓存兼容值 `unknown` |
| `transcription.timing` | `source`（字幕/识别结果时间）、`estimated` 或 `unknown` |
| `vision` | `outcome`、`describedFrames`、`totalFrames`；未启用、不可用、失败、部分完成及预算耗尽均明确区分 |

旧 `transcriptSource` 保留 `builtin/whisper` 契约，实际来源以新字段为准。缓存保存来源、时间精度与视觉覆盖信息，不把缓存请求误报成重新完成视觉分析；原有 `metrics` 仍记录本次请求的用量和耗时。

处理请求可选 `resumeOnly: true` 与 `analysisId`：严格恢复模式。沿用 process 鉴权、同源检查及限流桶；同会话同规范链接加入已有执行，已知分析 ID 时还需匹配原执行。已完成任务按归属/平台/视频和 TTL 查询缓存，恢复不调用平台解析、下载、ASR 或模型。未知会话、缺失/删除/过期任务返回统一 404；不创建新会话或分析。正常省略此字段的客户端继续使用原行为。

`GET /api/analyses/[analysisId]`：携带匿名会话 Cookie，按独立 `analysis` 桶每 IP 30 次/10 分钟限流。所有响应 `Cache-Control: private, no-store`。合法归属返回 `status`、`expiresAt`、`framesExpireAt`、`canFollowUp`；未知、越权、删除或不可用 ID 返回 404，不泄漏是否属于其他会话；限流返回 429 和 `Retry-After`。访问码已移除，不需要 `X-Access-Code`。

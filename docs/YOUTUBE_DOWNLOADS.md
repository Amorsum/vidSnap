# YouTube 字幕与音频下载

本轮延续 M1 第一批的计时/缓存改进，减少非缓存路径的重复平台解析，修复空字幕与后备音频格式问题。HTTP/浏览器验收按用户要求暂缓，发布前仍需补齐；本轮没有重试被工具策略拒绝的 HTTP 服务启动，也没有修改审批设置。

## 字幕优先路径

1. 首次 yt-dlp 元信息解析同时取得字幕清单，公开 VideoInfo 仍只有原有字段。服务端仅保留选定轨道，字幕签名地址不返回给客户端、不写入结果缓存或元信息文件。
2. 按元信息原语言优先选择一个人工轨道，再选择一个自动轨道作为备用。没有语言提示时沿用中英日韩等偏好；自动轨道优先 `-orig`，显式含 `tlang` 的翻译轨道不参与选择。只支持能由生产解析器读取的 VTT/SRT，不宣称未知语言信息下能够准确识别全部原语言轨道。
3. 轨道按 VideoInfo 对象身份和规范 URL 一次性交接，最多 32 条、可用期 2 分钟。复制对象、交接过期或容量淘汰后会重新解析；这不是跨会话共享缓存，也不是持久任务。
4. 选定轨道通过现有 Python 媒体出站边界直接下载，逐跳域名/DNS/固定 IP 校验保持有效。单文件最多 4 MiB、下载检查预算 20 秒；底层单次连接/读取有超时，外层 Node 留有 45 秒收尾预算，不把 20 秒描述成整个阶段的硬上限。
5. 下载后先检查普通文件、大小、非空字幕及有效时间区间（不超过视频时长 2 秒容差），再认为字幕命中。失败/空/损坏文件会清理，并尝试选定自动轨道。
6. 两个直链均不可用时，最多一次原 yt-dlp 下载器兜底，携带现有 Cookie 策略，只请求首选轨道；保留需要登录态或签名失效时的兼容机会。兜底有原先 30 秒命令预算、完成后的 4 MiB/内容检查，不额外宣称下载过程具有硬字节配额。仍失败则下载音频，继续 SenseVoice → Whisper 常驻/脚本降级。

正常字幕命中不再为下载字幕启动第二次平台提取，也不再先转换 SRT 才读取。下载结果内部附带 language/kind/delivery，描述人工/自动及 direct/yt-dlp 来源；主接口 SSE 和前端依赖字段保持兼容。本批没有修改客户端展示、云端估算时间戳、滚动字幕去重或模型解码策略。

## 实际媒体路径

音频仍优先 `bestaudio[ext=m4a]/bestaudio`。音频和低清视频统一读取 yt-dlp `--print after_move:%(filepath)j` 的最终 JSON 路径，不再假定音频一定为 M4A，或扫描目录取第一个同前缀文件。

路径必须唯一、绝对、位于当前任务目录内，视频 ID/后缀匹配、扩展名受限，并指向非空普通文件；部分文件、目录外输出、其他视频、同名目录或链接文件均拒绝。缺少实际文件时返回明确的内部错误，不将路径正文回显给用户。该处理参考 [yt-dlp 官方输出说明](https://github.com/yt-dlp/yt-dlp/blob/master/README.md#output-template)，没有升级依赖。

## 低成本真实媒体检查

```powershell
npm run --silent check:pipeline -- --workspace .\tmp\m0-session-validation --proxy http://127.0.0.1:7890 --media-only --json
```

`--media-only` 使用固定公开视频 jNQXAC9IVRw，先校验时长不超过 30 秒；通过生产处理器验证字幕，并额外下载一次音频以检查最终路径。正常应用在有效字幕命中时仍跳过音频下载。诊断只输出选定语言/来源、时间、文件大小和扩展名，不输出字幕、签名地址或本地路径；复用现有独立 Cookie/临时目录清理，不监听 HTTP，也不调用总结、embedding、ASR 或追问模型，因此不要求模型 API Key。

该模式对音频复用生产下载器的既有 120 秒预算，完成后检查不超过 8 MiB；不是新的生产磁盘配额。字幕的 4 MiB 是下载时上限。实际结果与回归见 [本轮报告](test-reports/TEST-20261022-M1-DOWNLOAD.md)。本轮没有 HTTP/浏览器、真实无字幕 ASR、真实抖音或完整视觉验收。

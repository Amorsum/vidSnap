# 同会话在途请求合并

`POST /api/process` 在平台解析前，按会话 ID、平台和规范链接取得单进程执行权。YouTube 的 watch、youtu.be、shorts 等分享形式会先归一化；同一会话重复提交时只运行一次解析、下载、转写、视觉、总结和向量生成。不同会话仍使用独立分析与产物，鉴权、来源检查及每次请求的限流先于合并。

首个请求保留原有 SSE 模型流。等待者接收最新进度和 analysisId，并维持各自的心跳；执行完成、媒体收尾后，从同一个分析缓存恢复结果，不重放已生成的模型片段。结果增加 `shared`：等待中的复用为 true，普通处理和普通缓存读取为 false。等待者的 `cached=true` 表示读取完成结果，并非请求开始时已有缓存。

等待耗时记录在 `metrics.timings.stages.inflight_wait`。等待者没有自己的模型调用，usage/cost 为 null，firstTokenMs 和 summaryReadyMs 也为 null；不会复制执行者的消耗或计时。resultReadyMs 仍是当前请求的结果就绪时间。

## 生命周期与上限

- 注册表最多保留 128 个正在执行的规范链接，每个最多 16 个等待连接；容量不足通过既有 SSE error 提示，不自动拆出重复执行。它约束本注册表，并不是所有历史路由或所有媒体子进程的全局并发预算。
- 单个等待连接最多等待 15 分钟，超时只移除自身订阅。首个执行不会因等待者离开而重启；超时后重试仍会加入正在运行的同一执行。
- 请求 abort 和响应 body cancel 都释放该连接的心跳、监听与等待名额。沿用既有策略：首个请求断连后执行继续，可供其他等待者和后续缓存读取使用；不宣称实现后台持久任务或进程取消。
- 执行失败时先按既有策略清理该分析，再通知等待者，移除执行键；之后可以重新处理。元信息阶段尚未创建分析的失败同样释放执行键。
- DELETE 先撤销分析写入权，再立即解除关联等待。新请求可以创建新的分析；旧执行随后返回时，不能保存旧结果、删除新的执行键或清理新分析的目录。
- 等待者和缓存读取者不拥有执行产物，不参与其 finally 清理。注册表仅保存最新进度、分析身份和完成状态，不保存字幕、问答、模型流或平台签名链接。

## 当前边界

这是单 Node 进程内的复用，重启后不恢复；运行中的条目只在执行收尾或明确删除后移除，不按等待者超时直接重新执行，以免制造重复下载和模型费用。底层调用若异常悬挂，仍依赖各自现有超时，必要时由运维处理。

尚未解析的不同抖音短码、抖音短链与直链不会预先视作同一视频；相同规范短链可以合并，解析后仍保留原有缓存复查。未持有有效会话 Cookie 的并发请求会建立不同会话，不能跨会话合并。配置/Prompt 版本缓存键、完整别名合并、可靠后台索引和持久队列仍在后续计划中。

本轮通过进程内生产路由和替身上游验证并发、隔离、失败、删除及断连，没有新增真实模型调用。HTTP 服务/浏览器验证按用户要求暂缓，发布前补齐。详见 [测试报告](test-reports/TEST-20261022-M1-INFLIGHT.md)。

# Whisper 本地转写的预算与故障恢复

M0 第四批把主接口与两个历史接口的本地 Whisper 调用统一到 `whisper-client.ts`。继续保留自带字幕优先、SenseVoice 云端其次、本地常驻进程及单次脚本兜底；本批不改 ASR 解码参数，也不宣称改善识别准确率。

## 调度与预算

同一 Node 进程的路由 bundle 共用一个客户端与执行槽。常驻推理与脚本兜底串行运行，最多额外等待 8 个请求，队列满立即拒绝；排队请求最多等待 2 分钟。排队满或超时不会变成另一路并行脚本。

| 预算 | 默认值 | 作用 |
| --- | --- | --- |
| `WHISPER_TIMEOUT_MS` | 600000 ms（10 分钟） | 从本地请求入队开始，包含排队、常驻启动、推理及最多一次脚本兜底的总期限；进度不续期 |
| `WHISPER_STARTUP_TIMEOUT_MS` | 120000 ms（2 分钟） | 模型预加载与协议握手期限，同时受请求剩余总预算限制 |
| 队列等待 | 2 分钟 | 与总预算取较早期限，到期移出队列，不提交给 Python |
| FFmpeg 预处理 | 60 秒 | 两个 Python 入口共用的转换超时，检查非零退出码 |
| 故障进程收尾 | 最多另等 1 秒 | 先终止旧常驻进程并确认 close，再考虑兜底或重建；无法确认则明确失败，避免再加载模型 |

两个环境变量只接受 1000—1800000 毫秒的整数，无效/空值沿用默认值。客户端首次创建时读取配置，修改后需由运维正常重启新版本服务；本轮没有重启现有用户服务。

主转写、历史转写、常驻预加载默认统一为 `WHISPER_MODEL` 或 `medium`。显式指定模型仍生效，包括既有短抖音 tiny 策略；本批没有调整它的质量策略。一个进程仍可能缓存不同模型，显存预算和模型淘汰留待后续。

## 协议与恢复

1. Python 完成默认模型预加载后，才发送 `{"type":"ready","protocol":1}`；Node 在此之前不发送任务。
2. 每个任务使用服务器生成的 `request_id`，所有 progress/result/error 响应必须匹配当前任务；旧 ID、重复和迟到响应不会完成下一任务。stdout 使用 UTF-8 增量解码，限制响应缓冲大小；stderr 持续消费，避免日志管道阻塞，不回显字幕、路径和异常原文。
3. 进程 error/exit/close、stdin 写失败、stdout EOF、协议损坏会结束当前等待。确认旧进程退出后，在剩余总预算内最多运行一次脚本；兜底仍占执行槽。后续未过期请求再建立新常驻进程，不重放已失败的原请求到新进程。
4. 在途总超时不再追加一份脚本预算；进度上报不会延长总期限。脚本自身使用剩余预算，超时终止该脚本进程。失败、关闭及队列状态均清理对应计时器。
5. 常驻与脚本结果检查 text、segments、有限非负时间及时间顺序。空片段保留为有效“无语音”结果，由主流水线给出已有提示；不编造文字或语言。历史接口没有语言时显式标记 `unknown`。

`whisper_audio.py` 用 context manager 管理转换 WAV：FFmpeg 失败、超时、推理迭代异常与成功均清理文件；网络协议仍限制为 `file,pipe`。主处理继续按分析目录清理媒体/帧并保留删除回写校验。

主 SSE 保留原事件与字段，在本地排队满、超时或服务失败时返回固定可操作文案，不把 Python 命令、私有路径或 stderr 显示给用户。历史接口沿用原 JSON 响应契约及错误状态。

## 验证与限制

`npm run test:security` 包含真实轻量 Node/Python 子进程的握手、分片、崩溃、stdout EOF、超时、写失败、队列和兜底故障验证，以及模拟模型的 Python 协议/文件清理和主 SSE 降级测试。测试不会导入真实 faster-whisper、加载 GPU 模型、读取生产密钥或调用付费 API。

这是单 Web 进程内的队列恢复，不能恢复 Web/电脑重启前的任务；不提供持久队列、租约、完整进程树取消或重连订阅。超时终止 Python 时，强制退出不能执行 Python finally；分析媒体由现有主流程收尾，但系统临时 WAV 的强杀扫尾仍需后续产物登记/持久 Worker 解决。脚本模型初始化也仍有冷启动成本。

第四批本身没有真实 GPU/CPU 推理、模型下载、长音频、多语言质量或性能评测；第五批已用缓存 tiny 与本机合成语音补充常驻转写冒烟，结果见 [运行环境检查](RUNTIME_CHECKS.md)。这不能代替默认 medium、自然语音、多语言与硬件性能验收。云端转写仍沿用历史 `source: whisper` 与估算时间戳，后续 M2 再修正来源与精度元数据；M0 的完整部署验收尚未完成。

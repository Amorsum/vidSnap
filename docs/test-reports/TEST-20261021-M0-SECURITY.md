| 隔离生产服务 HTTP 冒烟 | 18 组通过 | 17 组状态码检查 + 1 组跨三个处理入口的共享限流检查（前 10 次 400，第 11 次 429 且 Retry-After > 0） |

HTTP 检查覆盖首页响应、主处理/历史总结/历史转写/追问/删除的 401、合法鉴权后的异常 JSON/错型 ID/非法 URL/错误模式 400、缺失视频追问 404、访问码验证 200/401。首页 HTTP 200 只证明页面可响应，不视为浏览器交互验证。

隔离项目副本仅复制源码、配置、测试、锁文件及已安装依赖，不复制 `.env.local`、cookies 或隧道配置。测试服务仅监听 `127.0.0.1:3417`，使用测试访问码，不启动公网隧道，不修改原项目 `.next` 或停止既有服务。HTTP 测试只使用非法/缺失输入，不启动真实下载或模型调用，也不触发生产临时目录帧清理。

验证结束后，测试服务已停止，3417 端口不再监听。自动审批拒绝递归删除隔离构建副本（工具仅返回 `blocked by policy`，未给出更具体原因），因此保留 `%TEMP%/vidsnap-m0-validation-c60a16b5d5ec4324aad1f60563a152d0`；该目录只有本次验证文件和依赖，不包含真实配置或媒体。

验证中曾遇到测试替身的 promisify 符号/类型兼容问题，修正测试替换方式后自动回归及类型检查通过。第一次从原项目目录向外部副本运行 `next build <副本>` 时，Next.js 内部 `_global-error` 预渲染出现 `Expected workStore to be initialized`；随后在副本自身目录执行 `npm run build` 完整通过。该首次失败记录为隔离调用方式下的结果，不据此认定生产应用存在相同故障。

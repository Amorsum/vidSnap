# 分析刷新与连接恢复验证

日期：2026-10-26。学习辅助提交 `8c3ce28` 推送后接续实现，随恢复功能提交交付。

## 用例预期与结果

| 场景 | 预期 | 结果 |
| --- | --- | --- |
| 在途刷新 | 同标签页自动恢复一次，同会话加入原执行，无新增正常分析 | 通过 |
| 已完成但未收结果 | 只读有效缓存，复用笔记、个人笔记及分析 ID | 通过 |
| EOF/网络 | 明确未获得完整结果，保留旧笔记与恢复线索，手动继续 | EOF 通过；网络中断用流读取失败分支单测覆盖 |
| 401 | 门禁重新验证后可恢复 | 通过 |
| 429 | 保留线索，按 Retry-After 等待，不自动循环 | 通过 |
| 未知/越权/删除/过期 | 统一不可恢复，不新增上游调用；无会话不新签发身份 | 通过 |
| 分析身份 | 已知 ID 不加入同链接的替代执行；完成的抖音短链可按 ID 找回 | 通过 |
| 浏览器存储失败 | 恢复线索写失败仍能完成分析并保存笔记；畸形/过期线索被拒绝 | 通过 |
| 手机/键盘 | 375×812 和 844×390 无横向溢出，键盘 Enter 可操作恢复 | 通过 |

## 边界

这是单进程、同匿名会话的恢复订阅；不提供任务数据库、Worker、跨进程租约或重启恢复。恢复线索最长 2 小时，不延长正文 1 小时或帧 2 小时期。正常提交链接仍可能发起新的处理；仅 `resumeOnly` 保证不启动上游调用。没有实际物理断网、真实手机键盘或读屏设备验收。

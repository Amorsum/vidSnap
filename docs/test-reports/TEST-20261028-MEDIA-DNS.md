# 媒体独立 DNS 修复与验证

日期：2026-10-28

## 原因与修改

换用另一 B 站视频时，失败发生在元信息阶段。系统解析 B 站主站、API 及 YouTube 域名时返回 fake-IP，现有媒体边界按设计拒绝非公网结果。

- 增加 `MEDIA_DNS_MODE=system|doh`，模板保持 system，当前部署仅在 VidSnap `.env.local` 设置 doh。
- DoH 使用固定阿里公共 HTTPS DNS 和公开引导 IP；TLS 验证解析服务主机名，不经系统 DNS 获取引导地址，不接受请求指定解析服务器。
- 验证 DNS 问题域名/类型、状态、记录类型、TTL、JSON 大小；A/AAAA 地址合并后仍执行全部公网属性校验，媒体连接固定到该结果，目标 TLS 校验原域名。缓存不超过响应 TTL 或 60 秒、容量不超过 256 个域名。
- DoH 不可用、非公网结果、非法域名或端口均失败，不降级到不受校验的系统解析；页面区分 DNS 原因、普通策略拒绝和平台登录问题。
- 未修改系统 DNS、代理节点或全局代理配置。

## 自动与构建

- `npm run test:security`：253 项 TypeScript + 49 项 Python，共 302 项通过。
- 新增 DoH 测试覆盖固定引导地址/TLS 验证、响应错型/错域名/过大、HTTP 跳转拒绝、双栈缓存/TTL、固定目标 IP、混合公网私网结果拒绝、无系统 DNS 回退，以及 SSE 的 DNS 提示。
- `npm run lint`、根目录 `npx tsc --noEmit`、独立构建与独立类型检查通过；发布时根目录生产构建与类型检查通过。
- 原有媒体网络测试保持系统 DNS 模式，继续覆盖 443/受限 8082、路径与私网保护。

## 真实验证与部署

- 系统 DNS 仍返回 fake-IP 时，独立 DoH 对 B 站主站/API 返回的 28 个 A/AAAA 地址均通过公网校验。
- 同一个最新失败视频，使用实际应用配置，通过生产 Python 网络边界取得元信息，时长 1023.232 秒；音频分片 HTTP 206，读取 65536 字节。
- 完整音频下载成功，20,399,291 字节；FFprobe 时长 1023.232 秒。Cookie 仅使用临时副本，音频及副本已清理；未调用转写或模型，不保存字幕/回答。
- 备份旧构建后重新构建并重启 3100 服务，保留现有隧道；Chrome 公网入口 HTTP 200，输入框可见，无运行时错误。
- 此结果验证本次 DNS/媒体故障修复，不代表未来所有 CDN、网络线路或完整模型处理均可用；未扩大此前真实长视频/视觉/精度验收的结论。

当前默认解析服务与引导地址依据 [阿里云接入配置](https://www.alibabacloud.com/help/en/dns/httpdns-access-configuration)，同时经过本机真实 TLS 和解析响应验证。运维可将应用模式改回 system 以撤回独立解析，但系统 DNS 仍须返回真实公网地址。

## 失败详情与建议

本轮无失败用例。

### 环境相关说明（非代码缺陷）

1. **构建需代理**：直连网络下 `npm run build` 拉取 Google Fonts（Geist Mono）失败。建议在部署文档/构建脚本中注明需设置 `HTTPS_PROXY`/`HTTP_PROXY` 指向本机代理，或将字体改为本地自托管，消除构建对外网的强依赖。
2. **抖音仅验证失败路径**：受反爬环境制约，本轮未成功处理真实抖音视频。失败路径行为符合设计（错误消息保留 Python 侧真实原因）。建议后续在有可用真实链接时补充成功路径测试。

### 观察项（非缺陷，供参考）

- 客户端 result 事件中的 transcriptSegments 不含 embedding 字段（embedding 由 transcript-store 在追问侧合并），属设计行为；H1 retrievalSource=rag 证实向量检索链路正常。
- 首次管线使用内置字幕（transcriptSource: builtin）完成转写，SenseVoice 云端转写未触发，属正常策略（字幕优先）。
- 限流桶按 cf-connecting-ip / x-forwarded-for 取 IP：本机直连（无转发头）共用 "unknown" 桶；公网经 Cloudflare 隧道时各真实 IP 独立计数，实现符合预期。

## 成本与配额说明

- **LLM 调用共 3 次**：F 总结 1 次（1037 tokens，成本约 ¥0.0025）、H1/H4 追问 2 次。总成本约 ¥0.01。
- **转写**：F 命中内置字幕，未调用云端 SenseVoice（0 次）。
- **Embedding**：3 次（F 分段 1 批 + H1/H4 查询各 1 次）。
- **YouTube 元信息抓取**（yt-dlp）：13 次（F1 + G1 + J 10 次 + 隔离验证 1 次），均复用同一缓存链接。
- **限流配额**：破坏性限流用例（C3 11 次失败、J 11 次请求）全部使用伪造 IP（x-forwarded-for: 10.9.8.7 / 10.5.5.5）隔离，真实 IP 桶未受污染——测试后验证真实 IP 仍可正常处理（200 cached:true）。真实桶当前占用 4/10（F/G/I/隔离验证），verify 失败桶 0/10，追问桶 2/30。
- 测试后服务保持运行（生产服务已重启至最新构建）。

# 视觉阶段共享预算

主处理接口在完成字幕/转写后，进入视觉阶段时建立一个单调截止时间。低清下载、FFmpeg 抽帧、帧读取、模型响应正文、重试退避及备用模型共用剩余时间；每批、每个模型不再各自获得新的 90 秒等待。

默认预算为优化计划建议的 30 秒，可在 `.env.local` 设置 `VISION_TIMEOUT_MS`。仅接受 1000—120000 的整数毫秒值，无效配置回到 30000；`VISION_ENABLED=0` 仍可关闭视觉，缺少可选 Key 仍能总结文字。本轮没有修改实际生产环境变量或重启服务。默认值依据计划选定，尚未通过代表性真实视觉样本评估质量/耗时权衡。

## 执行与降级

- YouTube 低清下载把剩余时间按整秒向下取整，预留 2 秒给 Python 边界停止其 yt-dlp 子进程、关闭代理；剩余不足 3 秒直接降级。此处等待进程实际结束，不对文件写入进程做只返回、不收尾的 Promise 竞速。
- FFmpeg 使用不大于共享剩余时间的超时，超时发送 SIGKILL，并等待 execFile 结束。继续沿用本地文件协议白名单，保持任务目录及既有清理策略。
- HTTP 读取和模型响应正文使用可取消 signal，并有截止时间守卫；已收到响应头但正文挂起同样会超时。晚到的结果不会参与总结、补帧或触发更多请求。
- 单次可重试的 429/500/502/503 仍至多重试一次，2 秒退避计入同一预算；连退避都容纳不下时停止模型链。其他批次和备用模型也只使用余下时间。
- 到期或剩余时间不足以安全开始下一操作时，保留此前取得的画面描述；没有有效画面则继续文字总结。画面身份和时间仍来自原始 frameId/抽帧元数据，只有有效描述参与 Prompt、帧列表及追问证据存储。
- 每个阶段及新模型请求前校验分析仍有效。DELETE 撤销后不再启动后续批次或回写结果；已经发送的上游请求不承诺撤销计费。

预算约束的是视觉工作，不含此前平台解析、字幕下载/转写，也不约束随后的总结和向量生成。操作系统调度、文件系统调用、签名和进程收尾可能带来额外开销，不能把 30000 配置宣称为整个接口或浏览器的严格 30 秒完成保证。沿用现有 Python 子进程边界，不宣称实现所有派生进程的进程树取消。

## 指标契约

`result.data.metrics` 增加可选能力状态 `visionStatus`；没有在本次请求运行视觉（例如缓存命中或显式关闭）时为 null。原有 SSE 类型、transcriptSegments、frames、usage/cost 字段保持兼容。

| 字段 | 含义 |
| --- | --- |
| outcome | completed：完整覆盖；partial：部分覆盖；budget_exhausted：到期或余量不足；failed：其他视觉失败 |
| budgetMs | 当前视觉阶段配置的预算 |
| describedFrames / totalFrames | 有效描述数量 / 实际抽取的帧数量；抽帧前失败时后者为 0 |
| usageComplete | 每个已发送模型请求均返回有效 usage 时才为 true；超时或缺 usage 不能确认总消耗 |

完整覆盖在阶段计时中记为 completed，部分、预算耗尽和失败均记为 degraded，不阻断文字总结。降级原因通过 `visionStatus` 提供；页面提示展示可在后续界面批次接入。

`visionUsage` 只累计实际返回且数值有效的 usage，即使描述 JSON 解析失败也保留；`visionCost` 继续使用项目既有历史价格估算这些已知用量。`usageComplete=false` 时不能将其视为全部实际账单。没有 usage 保持 null，不伪造零成本，也不把历史价格描述成当前报价。

本轮测试采用替身模型与媒体进程，没有新增真实付费调用；真实视觉质量、下载器实际超时收尾及 HTTP/浏览器仍待发布前验收。具体结果见 [测试报告](test-reports/TEST-20261026-M1-VISION.md)。

# 本机发布与回滚检查

适用当前 Windows 本机生产服务与 Cloudflare Tunnel。此清单不使分析任务跨重启持久化；服务重启后旧在线追问需重新分析，本地笔记仍在浏览器。

1. 核对分支、提交、工作区和目标服务进程；确认 3100 监听者属于本仓库。保留其他进程、其他工作区修改及现有隧道。
2. 在不共享生产 `.next` 的环境执行 `npm run lint`、`npx tsc --noEmit`、`npm run test:security` 和 `npm run check:browser`。记录结果与版本；任何一项失败先处理，不发布。
3. 检查运行环境与必要配置是否可用，不打印密钥、cookies、隧道凭据、字幕或签名地址。真实平台与模型冒烟按单独预算执行。
4. 在项目内独立备份现有 `.next`，记录经过解析的绝对路径与版本。仅在确认身份后停止本项目 Next 服务；保留现有隧道。根目录构建失败时恢复原备份，再用 `scripts/start-services.ps1` 启动。
5. 构建成功后用 `scripts/start-services.ps1` 启动并核对本机首页、静态资源和受影响交互，再在浏览器验证公网入口。HTTP 200 本身不代表媒体处理与模型成功。
6. 发布失败时，核对停止的服务和备份路径均属于本仓库，将失败构建移至项目临时目录，恢复备份并启动；记录恢复结果。不得对未知进程或未核对的路径执行停止、递归移动或删除。

`npm run check:browser` 使用项目 `tmp` 内的独立副本、测试替身和临时端口，不加载 `.env.local` 或 cookies，不访问公网模型。依赖 Python Playwright 1.61.0 和本机 Chrome；测试服务与目录在退出时清理。可用 `npm run check:browser -- --fail-after-ready` 在隔离环境注入预期失败，验证异常清理；此命令有意返回非零。

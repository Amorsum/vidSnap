# 长视频转写与文字链路验收

更新日期：2026-10-28

## 处理方式

1. 保持视频自带字幕优先；仅无有效字幕时下载并转写音频。
2. 视频元信息超过 5 分钟，或音频文件超过 40 MiB 时，使用 FFprobe 获取实际音频时长，FFmpeg 以本地输入协议按最多 5 分钟切片，转成 16 kHz 单声道 AAC。元信息缺失时也先探测音频时长；超过 12 小时的分片任务明确拒绝。分片顺序处理，及时删除，错误或删除分析时停止后续分片。
3. 每段优先请求 SenseVoice，每个请求及响应正文默认最多等待 120 秒；云端失败后，从当前段开始使用本地 Whisper，不重新识别已完成的段落。本地请求保留原来的常驻进程、串行队列、脚本兜底和每次默认 10 分钟预算。中途切片或本地识别失败时提示具体片段，不能将不完整文本当完整总结。
4. 一段内没有识别到语音可跳过；全部片段无语音时返回明确提示。云端/本地混用时，兼容字段 `transcription.provider` 为 `unknown`，`timing` 为 `estimated`，不将混合结果冒充单一来源。本地 Whisper 的分段时间加上实际片段起点。
5. SenseVoice 只返回纯文本。云端结果在每个片段内按文本长度分配估算时间，再加片段起点；短视频按总时长估算。这里没有语音强制对齐，静音、语速变化或切片边界都可能导致偏差；页面和导出均标明“估算”，不能据此声称秒级精度。切片没有重叠，边界附近的词句可能被截断。

单片编码为低码率，避免整段大文件一次性驻留内存或上传。云端单文件限制请以 [硅基流动当前接口说明](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post) 为准。无云端密钥时按原有策略使用本地 Whisper；长片的每个本地任务按顺序进入现有队列。

## 限制

- 没有跨进程/服务器重启的持久分段续传或逐片检查点；失败需重新分析，单 Node 进程内的已有连接恢复语义不变。
- 分片上限为 12 小时，不是完成时间承诺。分析记录、源媒体目录仍沿用 2 小时运行生命周期；运行超过期限会停止，不能保证任何长度的视频均可完成。
- 不包含自动断句边界对齐、识别质量检测、长文本分层总结、精确时间戳或模型费用预测。
- 视觉、embedding 仍为可选能力；本轮真实文字验收关闭视觉，不代表视觉链路、转写质量或跨语言准确性已验收。

## 实际验收

- B 站公开短视频 19.26 秒：在独立临时目录直接调用生产路由，真实媒体与模型，关闭视觉。SenseVoice 转写 5 段，SSE 总结、一次追问、同会话缓存复用及删除通过；结果就绪 24.668 秒，总运行 27.778 秒。该数据为一次样本，不能外推总体延迟。
- 用户提供的约 41 分钟 B 站视频：真实媒体下载和 9 段云端 SenseVoice，生成 541 个估算字幕段；SSE 总结、一次追问、同会话缓存复用及删除通过。计时：下载 5.374 秒、转写 110.873 秒、总结 7.302 秒、embedding 4.496 秒、结果就绪 131.882 秒，总运行 138.488 秒。未对字幕内容或引用位置进行人工精度评测；关闭视觉。
- 两次验收均在隔离工作目录和进程内直接调用路由，不监听 HTTP，不占生产限流桶；Cookie 仅使用临时副本，媒体和结果在本次进程结束时清理。不输出字幕、模型回答或凭据。
- 短视频复验时平台元信息请求被媒体网络策略拦截；诊断的目标为 B 站域名，本机 DNS 随后返回 fake-IP，未改动用户 DNS 或代理设置。该失败不能计入完整通过，也说明当前网络仍可能波动。
- 自动回归覆盖真实 FFmpeg 片段生成、云端降级、本地失败、静音、删除、超时、时间范围、SSE/缓存与清理；`npm run test:security` 的 251 项 TypeScript 与 41 项 Python 共 292 项通过。`npm run lint`、根目录类型检查、独立生产构建和独立类型检查通过。

## 生产部署

用户授权后已备份旧 `.next`、完成根目录生产构建并重启 127.0.0.1:3100 服务；保留现有 Cloudflare 隧道。生产构建产物包含长音频分段逻辑，Chrome 公网入口返回 200，显示 Bilibili 输入且无浏览器运行错误。本次发布验证未再次调用真实转写或模型。

发布检查时本机 `www.bilibili.com` DNS 仍返回 fake-IP，媒体边界会拒绝非公网地址，因此公网入口可访问不代表 B 站解析此刻一定可用。未修改 DNS、代理配置或切换代理节点。

后续已为 VidSnap 配置独立媒体 DoH（`MEDIA_DNS_MODE=doh`），系统 fake-IP 保留但不再参与媒体域名解析；最新链接的真实完整音频下载验证通过。详见 [媒体 DNS 验证](test-reports/TEST-20261028-MEDIA-DNS.md)。

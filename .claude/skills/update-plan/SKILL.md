# update-plan — 更新改进方案进展

目标文件：`docs/IMPROVEMENT_PLAN.md`

## 执行步骤

1. **读取现状**：读取 `docs/IMPROVEMENT_PLAN.md`，定位「📋 执行进展日志」章节。
2. **判断本轮是否有新进展**：结合本轮对话完成的工作，以及 `git status --porcelain` / `git diff --stat` 判断。
   - 无实质进展（纯问答、没改代码/文档）：跳过第 3 步，直接执行第 5 步。
   - 有实质进展：执行第 3 步。
3. **更新日志**：在「执行进展日志」表格**最上方**新增一行：
   - 日期（`YYYY-MM-DD`）
   - 阶段（对应正文的阶段 A/B/C 或「上线修复」）
   - 本轮完成内容（一句话，简洁，不重复已有条目）
   - 涉及文件（1-3 个关键文件）
   - 状态（`✅ 已完成` / `🚧 进行中`）
4. **同步正文状态勾选**：若某改进项从「未开始/进行中」变为「已完成」，把正文对应条目的 `- [ ]` 改为 `- [x]`，其余内容不动。
5. **记录状态指纹（必须，最后一步）**：运行 `bash .claude/hooks/plan-state.sh record`，把当前 git 状态写入 `.claude/.plan-state`，让 Stop 钩子停止重复触发。

## 规则

- 只记录事实，不夸大、不虚构。
- 日志每行一句话，细节放正文对应条目。
- 不修改正文里除状态勾选外的任何内容。
- 无论是否有新进展，都必须执行第 5 步（记录指纹），否则钩子会重复触发。
